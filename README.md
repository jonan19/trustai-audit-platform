# TrustAI Audit Platform

A fairness, explainability, and governance audit of an AI loan-approval
system — built by combining six of the seven AI Ethics mini-project
experiments into one pipeline instead of six disconnected labs.

`ai-ethics` · `fairness` · `explainability` · `algorithmic-auditing` · `responsible-ai` · `streamlit` · `fairlearn` · `shap`

## Why this exists

Experiments 1, 2, 4, 5, 6, and 7 all turn out to be facets of the same
underlying question — *"is this AI system trustworthy?"* — just applied at
different stages: the data, the model, the deployment policy, and the
downstream advice it triggers. This project runs all of them, in order,
against one real classifier (an AI loan-approval model) so the results
build on each other instead of living in six separate reports.

**Experiment 3 (Deepfake Vulnerability) is intentionally excluded** — it
operates on unstructured media (video/audio/GANs), which doesn't have a
natural touchpoint in a tabular credit-decisioning pipeline. Everything
else is here.

## How the modules map to the lab experiments

| Module | File | Experiment | What it does |
|---|---|---|---|
| 1. Bias Autopsy | [`src/01_bias_analysis.py`](src/01_bias_analysis.py) | Exp 2 | Class imbalance, sampling bias, historical bias in the raw dataset |
| 2. Fairness + Explainability | [`src/02_fairness_explainability.py`](src/02_fairness_explainability.py) | Exp 5 | Trains the model, computes `fairlearn` fairness metrics, SHAP explanations |
| 3. Algorithmic Impact Assessment | [`docs/03_algorithmic_impact_assessment.md`](docs/03_algorithmic_impact_assessment.md) | Exp 6 | Formal risk assessment mapped to UNESCO + IEEE principles |
| 4. Self-Audit | [`docs/04_self_audit_matrix.md`](docs/04_self_audit_matrix.md) | Exp 1 | Exp 1's ethical evaluation matrix applied to *this* system, not a third-party app |
| 5. Drift & Autonomy Audit | [`src/05_drift_monitor.py`](src/05_drift_monitor.py) | Exp 7 | Simulates deployment drift, KS-tests it, recommends a human-in/on-the-loop policy |
| 6. LLM Resource-Bias Probe | [`src/06_llm_bias_probe.py`](src/06_llm_bias_probe.py) | Exp 4 | Tests whether AI-generated advice to rejected applicants favors expensive resources |
| Applicant Simulator | [`dashboard/simulator.py`](dashboard/simulator.py) | Exp 5 + 7 (interactive) | Scores a live applicant, then runs age/sex counterfactual probes to test disparate treatment |
| Dashboard | [`dashboard/app.py`](dashboard/app.py) | Exp 2 + 5 + 7 (visual layer) | Interactive Streamlit view tying Modules 1, 2, 5, and the Applicant Simulator together |

## Setup

```bash
pip install -r requirements.txt
```

## Running it

Run the modules in order — each prints its findings and saves charts to `outputs/`:

```bash
python data/load_data.py
python src/01_bias_analysis.py
python src/02_fairness_explainability.py
python src/05_drift_monitor.py
python src/06_llm_bias_probe.py
```

Or launch the interactive dashboard (Modules 1, 2, 5, plus the live Applicant Simulator):

```bash
streamlit run dashboard/app.py
```

### LLM probe: demo vs. live mode

`06_llm_bias_probe.py` runs in **demo mode** by default (a rule-based mock
model), so the whole pipeline works with zero API keys. To probe a real
model instead:

```bash
pip install anthropic
export ANTHROPIC_API_KEY=your_key_here   # (Windows: set ANTHROPIC_API_KEY=...)
python src/06_llm_bias_probe.py
```

## Headline findings (from a real run of this pipeline)

- **Historical bias**: 7.5 percentage-point approval-rate gap by sex (72.3%
  male vs. 64.8% female); under-25 applicants approved at only 57.9% vs.
  77.8% for 60+.
- **Model fairness**: Demographic Parity Difference = 0.040, Equalized Odds
  Difference = 0.112 (above the ~0.1 concern threshold); female applicants
  have a higher false-positive rate (0.848 vs. 0.737).
- **Drift**: no drift detected in the baseline window; from "Quarter+2"
  onward, 75% of monitored features show statistically significant drift
  (KS test, p < 0.05) — the audit's own policy engine recommends withdrawing
  full autonomy at that point.
- **LLM cost bias (demo mode)**: average price-rank of the recommended
  resource rises from 0.45 (budget-constrained prompt) to 0.80 (cost-neutral
  prompt) to 1.35 (unconstrained prompt) — consistent with Cost-as-a-Proxy
  bias.
- **Counterfactual fairness (Applicant Simulator)**: on the default
  borderline applicant (age 22), flipping ONLY age to 60 flips the decision
  from Rejected (43.8%) to Approved (52.2%) — direct evidence of age-based
  disparate treatment, since age is a real model feature. Out of the full
  dataset, 41 applicants flip decision on an age swap and 24 flip on a sex
  swap when tested against a sex-aware variant of the model (the production
  model itself never sees sex — see `docs/03_algorithmic_impact_assessment.md`
  for why proxy discrimination persists anyway).

See `docs/Final_Report_Outline.md` for how to assemble these into the
document you actually submit.
